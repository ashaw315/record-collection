# Withdrawals

The withdrawal list for all six targets: the two record-detail targets, the wall, the nav, the record modal, and the table and grid. **Nothing is written into a target to mark a withdrawal:** each entry quotes its withdrawal sentence verbatim from the section it withdraws in, and the index script checks the quote is there.

**A withdrawal sentence and its entry land in the same commit.** That is the guarantee: neither half is ever in the repo alone, because an entry without its sentence fails and a sentence without its entry is an undeclared withdrawal. Where one author can reach both files, Claude writes both in the same edit. Where the sentence's host is in Code's region, the drop carries the entry and the proposed sentence, and Code writes the sentence into its region in the commit that takes the drop. **Where the host file is not an index input, the entry waits until it becomes one,** and the sentence is held in the handoff until then; Code files both in the commit that makes the file an input. If a withdrawal sentence is later rewritten, its entry fails and names itself; re-quote it in the same commit.

**When an entry is owed.** A correction earns an entry when the claim was in force and is now false for some real case. In force means built against, or carried in a drop Code has taken. A correction to a section's own wording before anything was built against it is a draft fix and needs no entry, however much the wording changed. The test says when an entry is required, not when one is forbidden; over-filing costs nothing. It was stated after five rulings in one day had to argue the question from scratch, and one of them, §28's 240 and §33's foot-passing, missed an entry it owed.
