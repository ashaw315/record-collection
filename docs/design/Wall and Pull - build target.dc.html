The wall and the pull — build target

Moved unchanged from Record Detail 8a — build target, where it was §11. The only edit is the renumbering §11.N → §W.N, applied to headings and references in both files. Sections cited here without a W (§3, §5.5, §8 and others) are in the record-detail file, and the practice at the head of that file applies here.

W · The wall, and what the pull is for

The wall at rest is line, ink and paper: no derived colour anywhere in the drawing. Colour arrives with the pull. A record on the shelf is one of seventeen outlines; pulled, it becomes itself and takes its own colour. So the pull is not only motion — it is the transition from the collection to a record, and colour is what marks the transition. Every other surface keeps colour and ornament; the wall at rest is the exception, and the exception is what gives the pull its meaning.

This also settles what A62 measured and could not act on: the fills read as texture rather than identification, and a monochrome shelf stops asserting an identification the fills were never making. Withdrawn with it: the two-screen colour defect, the two collisions, 5b’s four-candidate ink pick at rest, and the whole clamp question on the wall side — all four were arguments about which colour a spine takes, and a spine at rest takes none. The earlier §W ruled the spine’s raw value canonical and withdrew this page’s clamp to match it. That is reversed: nothing on the wall reads the value at rest, so nothing constrains this page, and the clamp is reinstated as §5.2 states it. The drawings are re-derived back to the clamped base and its three ladder steps — the same 132 literals, moved twice now, which is the cost of a ruling on one screen reaching into another’s rasters.

W.1 · What distinguishes a spine at rest

Position orders, width textures, the label identifies. Position carries the collection’s order rather than the record’s identity; the label identifies exactly, and only at reading distance; width is texture across the shelf and distinguishes nothing. An earlier version of this paragraph made width the channel the eye uses before reading, on the ground that it is the only one of the three derived from the record — spineWidth hashes the id. The next paragraph is why that is wrong.

Width is not a difference channel at any size, and the 200-record drawing measures it rather than predicting it: spineWidth yields eight integer values, so at two hundred each is shared by about twenty-four records and a 1px step between neighbours does not read at all. At seventeen sixteen records already share a width with another — so the seventeen case was never passing on width; it was passing on the label, and the width channel was carrying nothing the whole time. That is sharper than "not enough at two hundred" and it retires the sentence above: width is derived from the record, which made it look like the identifying channel, and being derived is not the same as being distinguishable.

So the label is the only channel that distinguishes, and the open work is keeping it readable rather than adding a second mark. A truncated label is the one failure that removes identification outright, which makes pitch, wrapping and the cap the density work rather than ornament. No truncation count is quoted here, and the reason is narrower than the one first given: the budget did not move — 37 stands (§W.6) — so Wall Density's count is invalid for the reason it always was, that it was gathered at 36 against a code value of 37. It needs re-gathering at 37 or dropping, and those are different reasons for the same action. The general form still holds and is worth keeping: when a parameter does move, a count derived from it is not stale pending re-measurement — it is not evidence at all until someone re-gathers it, and an argument that can stand on arithmetic should not wait for one. A difference rule over widths would be a rule over a channel that does not read; and colour at rest returning as a distinguishing device would spend the ruling above on a density problem it was not addressing. The honest summary of the rest state: position orders, width textures, the label identifies.

W.2 · When the colour arrives

The clock and the single curve are withdrawn for the pull: the span is 1600ms out and 860ms back (§W.21) and the phases overlap (§W.19), so the colour fade runs the full out-span rather than 1000ms. Left at 1000 it would reach full colour 600ms before the record lands. What survives is this section’s actual subject — that colour arrives across the gesture rather than at either end of it — which is a ruling about when, and independent of how long. The single curve also still governs every motion that is one motion; §W.16 lifts it for the pull alone. What follows is the withdrawn clock.

Across the gesture, on the same curve, and not as a fourth property of it. The motion is one 1000ms ease-out cubic driving translation, scale and shear together, and the single curve is load-bearing: if scale finished first the grown rectangle would untilt and read as it turned rather than it came off the shelf. Colour joins that curve as a fade from paper to the record’s clamped base, over the same 1000ms, starting at 0.

The alternatives are worse for stateable reasons. Colour at the end reads as confirmation — the record lands, then lights up — which makes the colour a response to the motion rather than part of it, and puts an event on a curve whose whole argument is that it has none. Colour at the start reads as the shelf changing before the record moves. Across it, the record is becoming itself while it comes toward you, which is what the pull means.

One consequence, because it is a reversal on the same curve: the return is not the pull played backwards for colour. Colour leaves on the same fade, since a record going back becomes one of seventeen again — but the fade to paper must complete before the spine reaches the shelf, or a coloured spine sits in the rest state for the last frames and the exception leaks.

W.3 · What the pulled record shows

The cover, with the record’s colour as the field behind it rather than a wash over it. The cover is the record’s own material and §5 already calls it the entry point and the source of the colour — so the pull arriving at the cover is the pull arriving at the thing the colour was derived from. A field of derived colour alone would be the pull arriving at a swatch, which is the identification A62 found the fills were not making.

And it is a cover at its own aspect, not cropped: the record screen shows 83% of a square sleeve at 1440 and 47% at 2560, a cost paid for a fixed band, and the pulled record has no band to fit. The pulled state is the one surface in the app that can show a whole sleeve, so it shows one.

The record with no cover arrives at type, not at a swatch. §W.3 as first written ruled the covered case and left the seventeenth record arriving at a #3a3a3a square — precisely the swatch the section forbids. With no cover the record's material is its text, so the pulled state sets title and artist large on ink — not on a colour field. An earlier version of this sentence put them on “the same clamped base every other record fades to”, which has no referent when the sample is null (§W.8): §5.3 owns the fallback and §5.3 says ink, and the honest reading is that colour arrives with the pull because it comes from the cover, so a record without one has none to arrive with. The absence takes §6's diagonal across the empty sleeve area, so the pull says no cover rather than showing a grey rectangle and leaving the reader to infer it. “On ink” names the face’s ground, in contrast to a colour field, and does not place the type. The empty sleeve area is §6’s no-cover frame, at paper luminance, set inside the ink field with its diagonal, and the title and artist are set in that area. So the build’s paper square inset in the ink field is faithful, and this is a clarification, not a withdrawal. It is settled, by Adam’s ruling. Two independent readings converge on it, the sentence read with §6, which it cites, and the build, and one argument decides it alone: ink type on an ink ground cannot be read, and nobody wrote a design where the type cannot be read.

W.4 · The record screen’s contrast findings, which are independent

With the clamp reinstated, the 72’s failures go with it: Grave New World at 1.43, Loss Of Life at 1.77 and the null-spine record at 1.00 were all consequences of withdrawing the clamp, and Super Rich at 3.03 returns inside the band. That is the clamp’s actual job, now stated correctly — it exists so the field clears its headline allowance on every record, not so two screens agree.

The 11px label finding is independent and was true before any of this: fourteen labels reading 3.88:1 against paper, below 4.5. Fixed rather than ruled around — mono label ink moves from oklch(0.48 0.008 70) to oklch(0.44 0.008 70), which reads 4.62:1 and keeps the label below body text in the ink hierarchy. It is one value in 158 places, and the reason it survived this long is that contrast is checked against the ground a mark is drawn on, and these were checked against nothing — paper is the default, so the failure had no site to be noticed at.

W.5 · Which paper the ratios are measured on

The drawing's 0.925 is the page's paper and the app should paint it; --background at 0.985 is the value that moves. Not because the drawing outranks the build — §W.4 has just been corrected the other way — but because every other value in this system was chosen against 0.925: the 0.72 hairline, the 0.18 ink, the 0.44 label, and the ladder's tint step, which is literally derived as a fraction toward paper. Repainting the ground at 0.985 rescales all four relationships at once, and the hairline is the one that cannot survive it — §3 spends its whole argument keeping a rule at the threshold of visible, and that threshold is a contrast, not a lightness.

The general rule, which is the part worth keeping: a contrast ratio is measured on the ground the app paints, so the two numbers have to be one number. The 3.88:1 label finding was measured on 0.925 and the app's label actually read 4.64:1 on 0.985 — the fix stands at 0.44 because it clears both, but it was ruled against a ground the page does not have. That is the coincidence-for-a-margin shape once more and the fourth instance: two values agreeing closely enough that nobody asked which one was being measured. So paper is one token, named in both places, and every ratio in this file is measured against it — and the four ratios derived this round (6.32, 5.4, 4.62, 2.6) are measured on 0.925 and stand only once the app paints it.

One item confirmed in scope rather than left to be inferred: §5.2's release-year label strip is a build item, not a drawing-only refinement. The 30px paper strip above a 120px coloured block is drawn in every raster and is not built, and the rule behind it — the field is ground for one figure — does not depend on the contrast figures that first produced it. And the null-spine 1.00 was live rather than a consequence of the withdrawal: recordLadder(null) is null under any clamp, so §W.4 cited it as evidence for the clamp when it was evidence for §5.3's fallback. Fixed on the rendered route, and the citation is corrected here.

W.6 · Scale, the empty run, and the label threshold

D2's figures are ratios and 5b's 240 is the scale — Code's reading is confirmed. The reason is the 9px floor: 150 × 12 at 1:1 sets a 9px label across a 12-unit spine, so the drawing would specify a label wider than the face it sits on. Adopting the ratios at 240 lands every D2 number where the build already is — thickness 19.2 inside the hash's 17–24, the 6.5 label at 10.4 against the built 10.39. Stated as the rule so the 1.6× is not read as drift: D2 specifies proportions, 5b specifies the unit, and a figure in D2 is only a number once multiplied. The two exceptions are the ones that do not scale — the 9px floor is an absolute in text-micro, and the character budget is 37, derived from the face at either scale, and it is spine-text.ts with a test on the derivation rather than the answer. Face less the baseline inset, over the measured advance: floor(232 / 6.235) = 37 at 5b's unit, and floor(145 / 3.9) = 37 at D2's. The two agreeing is the check, and it is what a transferable budget looks like.

This was withdrawn for one round on arithmetic that used the wrong advance, and the error is worth stating because it is the narrowest one in this file. The withdrawal computed 260px against a 240 face using an advance of 7.03 — D2's 6.5px size plus its 0.5px letter-spacing — which is the estimate the same round had just conceded was wrong, applied at the other scale. The measured advance is 0.6em and nothing else: 6.235px at 5b's 10.39 label. So checking a spec figure against the face is not sufficient; it has to be checked with the measured advance, and the measured advance is the one number here that was read off a rendered label rather than derived. D2's 30 is the superseded figure and its letter-spacing is removed, since the advance the cap divides by has to be the advance the label is set at.

A run with no seated records still has a shelf. The plane was built from shelfRuns, which drops an empty run, so a shelf holding one pulled record lost the plane the record was pulled from — and §2 does not address it because §2 describes arrangements rather than the absence of one. The rule: the plane is a property of the shelf, not of its occupants, so it spans the seated arrangement whether or not anything is seated in it. A record pulled from a shelf is still pulled from somewhere, and the plane is what says so.

And the threshold is D1's answer rather than a scaling rule: the wall never fits the collection into the viewport. §5 removes labels below 1:1 and never shrinks them, which is right — but §W.1 makes the label the only channel that identifies a record, so a wall below 1:1 is a wall of unidentified outlines, and at 200 records on a 1440 viewport that is the whole shelf. So the wall renders at 1:1 and pans; it does not scale to fit. The overview at 200 is a different view with a different job, not this one shrunk — which is also why the 24px-pitch comb read as structureless: it was this drawing asked to do the overview's work. The label switch stays built as specified, as the guard for viewports narrower than one record, not as the mechanism for showing the collection.

The paper divergence is now visible against the app chrome, which is §W.5 working rather than a new defect: the composition paints 0.925 and the app paints 0.985, and §W.5 rules the app is what moves. The visible seam is the measurement — a ground that reads as a panel against the chrome is what a wrong paper looks like, and it will close when --background does.

W.7 · The plane’s extent, and where the panel sits

One plane, one width, every row — the wall’s width, with the records inset inside it. Spanning each run’s seated extent gives four planes of 456, 433, 434 and 430, ragged by 26px, and a shelf whose length is a function of what is on it is not a shelf — it is a platform per arrangement, which is why the rows read as islands with the pitch measured correct at 1.272 against D2’s 1.271. The width is the pan extent — the plane runs the full width of the wall and off both edges of the viewport (§W.8). An earlier version of this sentence made the width a capacity, on the ground that a width derived from the fullest row moves every plane when one record joins that row; the ground holds and the answer did not, because a capacity is still a count, and forty per shelf leaves the collection an eighth full while sixteen is wrong at the eighteenth record. A fixture must not be sized by a count at all, and the thing being drawn is a fixture rather than a measurement of the collection. So the plane is the wall and the collection sits in it — which is also what makes an empty run’s plane (§W.6) unremarkable rather than a special case.

And §2’s section breaks are marks within the plane, not the plane’s ends. They currently coincide because each plane stops where a section does, so the break is being read off the fixture’s edge — the same defect one level out: a division of the collection expressed as a division of the furniture. A break is a rule across the plane at the seat boundary, and the plane runs on past it.

The panel is kept and §10b’s content is its content — the ruling is where it sits. §W.3 rules what the object shows, D2 rules how it arrives, and neither mentions text; §10b rules that every fact leaves the object for a panel beside it. Those agree rather than conflict, and the panel is what the gesture arrives at, so: it sits in the plane of the page, not in the projection — flat, on paper, at the record screen’s type and rules. Nothing in the panel is sheared. Where exactly is withdrawn to §W.9: this section placed it to the right of the pulled record and aligned to the cover’s top edge, which positions a destination against a moving object, and §W.9 gives it a fixed framed region in the page’s left column instead. What survives is everything in this paragraph that is not a position. The projection is what the collection is drawn in; the record’s facts are read, and §4.1’s split already says reading matter is set flat.

Two consequences worth stating rather than leaving to the build. The first is withdrawn: this section derived the panel’s width from the cover’s projected width so that record and facts would occupy one measure — and called that pair “two columns”, which is not §W.9’s two columns and would now name the same phrase for two different structures. Under §W.9 the panel’s width is its column’s and the record takes the drawing region entire. And Turn over survives, because it is about the record rather than about which face is toward the reader: the pulled state shows the sleeve’s front on the right face, and turning it over shows the back on the same face. A control that flips the artwork does not depend on the face carrying it.

The no-cover record arrives at type, and §W.3’s own sentence forces it: the pull must not arrive at a swatch, and one record of seventeen has no cover, so the covered case is not the general case. With no cover the record’s material is its text — title and artist set large on ink, on the face where the cover would be — and §6’s diagonal crosses the empty sleeve area so the state says no cover rather than showing a grey square and leaving the reader to infer it. That is the one place text enters the projection, and it does so because it is standing in for artwork rather than being read as fact.

The frame defect is worth recording for its shape: the extent was computed over planes and front faces while the top faces stand D·sin30 above them, so the top row ran off the viewport. A bounding box taken over a subset of the geometry it is meant to bound — and the subset was the faces that existed before the top face was added, which is the enumeration shape §9.2 records, arriving in the frame calculation.

W.8 · The accessibility contract, the fork, and two contradictions

The spines are anchors inside the SVG, not a list beside it. Five specs the lit wall met — a spine is a link and works without JavaScript, it names its record by role, the wall shows what its heading says, every record carries its full title, and a keyboard can walk the wall and open a record — are a contract the swap cannot drop, and they are ruled here because the panel is what those links open. The list was the lit wall’s mechanism and it would put a second representation of the collection on the page; §W.1 already makes the label the only identifying channel, so a parallel list is the identifying channel drawn twice, in two vocabularies, with nothing saying which is the wall. An <a> wrapping each spine’s faces keeps one representation: the href is the record’s route, so it works with JavaScript off, and the full title goes in the accessible name where the face carries the truncated one — which is the only place in this design where truncation is not a loss.

The one thing that has to be checked rather than asserted: SVG has no z-index, so paint order is document order, and document order is what a keyboard walks. Those could disagree — a drawing painted back to front and read left to right is two orders over one list. They do not, and the reason is worth recording: within a row the seats vary only along x, so the back-to-front sort by x + y is already seat order, and shelves run top to bottom in both. So one order serves the painter and the reader, and no tabindex is needed — which is the check to keep, because the day a row’s seats vary in depth the two orders separate and the drawing silently gets a wrong reading order.

The no-cover field is ink, and the other two candidates fail on their own terms. #3a3a3a is a default colour, which SPEC §4 says never renders — a value invented to fill a null is exactly the fill that section forbids. §W.3’s “the same clamped base every other record fades to” has no referent when the sample is null, so it is not an answer but a sentence written without the null case in view. §5.3 owns the fallback and §5.3 says ink, so the pulled state of a record with no cover is type on ink with §6’s diagonal — no colour, which is also the honest reading: colour arrives with the pull because it comes from the cover, and a record with no cover has none to arrive with.

The size is fitted to the square rather than taken from the scale, and that is not an exception to the scale — it is the scale not applying. §4 governs type that is read; this type stands in for artwork, so it is a drawn element and its size is derived from its box, which is what the 72 does in the year field and what §9.2’s ornament does in its cell. Five lines of headline type in a 188px square is a paragraph, and no size on the scale fixes that, because the defect is that a size was chosen at all. The fit: the title sets to the largest size whose longest word fits the square’s measure, at most three lines, anchored top so a clip takes the tail rather than the head — floored at the scale’s 15, below which it truncates at a derived cap like the spine label (§W.6) rather than shrinking further, since type too small to read stands in for nothing. The artist sits above it at LABEL, which is read rather than drawn and therefore does take a scale size.

The fork at 820 is withdrawn with the premise it rested on. This paragraph argued the overlay from the panel competing with the projection for width; under §W.9 it never does, at any viewport, because it has a column of its own. So the narrow-viewport question is now whether the two columns stack, and it is deferred rather than answered — a stacked facts-over-drawing page is a different composition from the one §W.9 rules, and A32’s collapsed panel was an answer to an overlap that no longer happens. The projection does not reflow: the wall renders at 1:1 and pans (§W.6), so a narrow viewport shows fewer records rather than smaller ones, and whatever the stacked composition turns out to be, the projection inside it is unchanged — which is the one thing the deferral does not defer.

Arrows between pulled records are kept as the old screen has them — wall order, absent at the ends, a slide at the same depth. §W never mentioned them, and the omission is the shape this file keeps finding: §W.2 ruled the gesture from the shelf and nothing ruled movement between two records already off it. The slide holds depth because the record is already pulled: changing depth would be a second pull, and the arrows are movement along the collection rather than into or out of it.

Capacity is withdrawn as the plane’s measure — the plane is the wall, and the wall is the pan extent. Forty per shelf leaves the collection an eighth full and reads as a fixture waiting to be stocked; sixteen fits today and becomes wrong at the eighteenth record. Both are the same defect the ragged plane had: a fixture sized by a count. The plane runs the full pan extent and therefore off both edges of the viewport, and a fixture that ends inside the view is what reads as a platform — which is what §W.7 was reaching for in saying the records sit in the plane rather than the plane under the records. At seventeen the wall is a shelf the collection sits at the left of, and that is a true statement about the collection rather than an empty fixture.

W.9 · Two columns, and where the pull lands

The page is two columns: facts left, drawing right, with the rule between them running the full height. The left column carries COLLECTION and the count at its head, and below a hairline a framed region that is empty at rest and holds the panel when a record is pulled — §10b’s content, flat on paper, at the record screen’s type. That fixes the panel to a region rather than positioning it against a moving object, which is what every previous attempt was doing and why each one needed a new rule: §W.7 sized it against the cover, §W.8 overlaid it below 820, and both were answers to “where is the object now”. A destination does not move, so it needs no scrim, no lightness step and no overlap ruling, and the left third stops being empty at rest — it is a region that is waiting rather than a margin that is unused.

The record lands in the drawing’s region and takes it entire — the largest parallelogram at the wall’s angle the region holds, over the wall it came from. An earlier version of this sentence made it the largest square, unsheared; §W.10 withdraws both — what survives is that it takes the region entire rather than sharing it. §W.2’s single curve was built for exactly this and the geometry is exact: the right face is the cover, so the face already toward the reader is the one that grows — and it stays sheared through the pull, then turns: §W.10 withdrew the straightening and §W.14 restores the square as a second phase’s end rather than as this phase’s geometry. A face resolving to zero shear is geometrically a face meeting the reader, and it lands as an axis-aligned square with no relationship to the drawing beneath it. It takes the whole region rather than sharing it with the panel, because the panel has a column of its own; an earlier proposal made it the larger of two equal columns, which was still sizing the object against its facts.

No lightness step behind it. The step was proposed when the panel sat over the drawing and needed separating from it; with the panel in the left column the only thing over the wall is the record, and a record in front of a wall reads as in front of it because it is larger and its seat is empty — two differences, and the second is the stronger one because it is a change in the wall rather than in the record. This paragraph first cited square and unsheared as two of three differences, and §W.10 withdrew both, so the step is refused on scale plus the empty seat. A step would be a scrim by another name, and §W spent its whole argument on the wall at rest being line, ink and paper.

The count stays at the column’s head and the panel fills the region below it. COLLECTION and the count are the collection’s identity, not the record’s, and the wall is still there behind the pulled record — a panel that replaced the whole column would say the collection had been left, which is the opposite of what the pull is. The hairline between them is already drawn at rest, so nothing moves when the panel arrives.

The arrows belong with the record, not the panel. They move along the collection and the record is the thing that slides, so an arrow against the panel is a control placed with the facts rather than with the object they describe — the same misplacement the panel itself had, one level down. Wall order, absent at the ends, at the record’s edges in the drawing’s region.

Rows are a fixed length, not filled to the view, and §W.8’s no-reflow rule extends to wrapping. §W.10 sets that length from the unit’s proportion rather than as a capacity; the reasoning below is why it is fixed at all. It was written about sizes and the reason reaches further: a record that changes shelf when the window narrows has a position that is a fact about the viewport rather than about the collection, and §W.1 leaves position carrying the collection’s order. The plane still runs the pan extent — that is what stops the fixture reading as a platform (§W.8) — but the seats per row are fixed, so the wall is a shelf the collection sits at the left of and the plane runs past it. A row’s length and a plane’s length are different quantities, and conflating them is what produced both the ragged plane and the empty one.

W.10 · The unit, the pull in projection, and two views

The wall is a fixed unit of four shelves joined at their ends, and the collection fills it left to right, top to bottom. Capacity 40 produced one row of seventeen running off the right edge, and the diagnosis is the one this file keeps making: capacity is a count per row, and what makes a shelf read as a shelf is the shape of the stack. Those are different axes, so the parameter could not reach the property — at seventeen records nothing stacks, and the wall becomes furniture only at the forty-first. The row length is therefore set from the unit’s proportion rather than from the collection: four shelves and a row length that make a unit taller than it is wide, which is what the reference is and what §W.8 was asking for in saying a fixture must not be sized by a count.

The shelves are joined at their ends and nowhere else. 5b rules out a carcass because a box around the collection competes with the records standing in it, and that holds — but four planes with nothing joining them is not a shelf either, and the reference gets its solidity from the stack rather than from a box. So: the four planes, plus the vertical members at their ends that make them one unit. No back, no front, no top. The empty shelves draw — §W.6 already rules an empty run keeps its plane, and at seventeen records three empty shelves are the fixture rather than a gap in it. Above one unit’s worth the wall gains units, and the pan extent is what holds them, so the row never lengthens to fit the collection.

The pulled record stays in the projection for the whole of the pull: it slides forward along the depth axis and grows, and it does not straighten while it is coming out. §W.14 adds the phase after it — once clear of the row the record turns and squares up, so this section governs phase one and the flat square is phase two’s end state rather than a withdrawn answer. §W.9’s “the face straightens and grows” is withdrawn. It was geometrically true — the right face is the cover, so a shear resolving to zero is that face meeting the reader — and the result is a flat axis-aligned square with no relationship to the drawing it sits on, which reads as an image pasted over a line drawing. The whole argument for the isometric was that everything on the wall is one drawing, and the pull was the one place that argument was being spent. So the cover arrives as a parallelogram at the wall’s own angle — large, unmistakably the cover, and still part of the same drawing.

And the seat empties. A record cannot be in the row and in front of it, so the pull leaves a gap at its seat — which is what a record off the shelf looks like, and it is also the return path drawn: the gap says where it goes back. That the spine stayed put was the same defect one level down: the pull was adding an object rather than moving one.

D1 reopens and the answer is two views, because the earlier ruling was stated over the wall when its reason was about reading. “A sub-1:1 wall is a shelf of anonymous outlines once the label is the only identifying channel” is true and it is an argument about identification — which is the near view’s job and not the far view’s. The far view answers how much there is and how it is arranged; identification there is not failing, it is not being attempted. The comb was this drawing asked to do the overview’s work, and the row is the overview asked to do this drawing’s — one view failing two jobs in both directions, which is the granularity shape §9.2 records arriving at the top level of the screen.

So: a far view of the whole unit with no labels, and a near view at 1:1 that pans and reads. Labels are absent in the far view rather than shrunk — §W.6’s threshold already says type too small to read stands in for nothing, and it is the same ruling as the sleeve fit. Movement between them is the same gesture as the pull, one step out: the far view zooms to the near view at the point addressed, so the sequence is collection, then shelf, then record, and each step is the same motion at a different scale. What must not happen is a third drawing — the far view is this unit seen whole, not a diagram of it.

W.11 · The three drawings, and the figures they fix

§W.10 made three claims about how something reads and none of them had been drawn. Every claim of that kind in this project has needed drawing before it was true — the corner triangle, the comb, the islands — so these are here before the build rather than after it. The polygons are the measurement and the prose is written from them, which is the opposite of how the first version of this section was assembled and the reason it disagreed with itself in five places.

Far view, 17 records — one unit, top shelf occupied, three shelves empty, labels absent. 442 × 1047 units, 1 : 2.37.

The empty shelves hold. W.14 · The pull has two phases, and the square is the second one’s end

Out, then round. The record leaves its slot in the projection, and once it is clear of the row it turns to face the reader and squares up. §W.10 and §W.9 were both right and both stated over the wrong subject: §W.10 ruled the record stays sheared and §W.9 ruled it lands square, and each wrote “the pull” when it meant one phase of it. A rule stated over a gesture when its subject is one phase of that gesture — which is the granularity shape again, now in time rather than in geometry.

§W.2 is not reversed. It is scoped, and the scope was always phase one. Its argument is that a gesture’s parts must not finish at different times — a scale completing before a shear reads as it turned when nothing turned. Here something does turn, so the reading that argument exists to prevent is the reading being asked for, and it is being produced by an actual rotation rather than by a timing artefact. A second gesture after the first completes is not a part finishing early. So the single ease-out, the 1000ms and the one curve driving translation, scale and shear together all stand, unchanged, for the pull.

The two phases abut with no hold, and the boundary is legible from the velocity rather than from a pause. The pull is ease-out, so it arrives at rest; the turn is ease-in-out, so it leaves from rest. Velocity returning to zero between them is what makes two motions read as two — a hold would make it read as a stall, and a shared curve would make it one motion with a kink in it. That is the same instrument §W.2 used, applied to the join rather than to the parts.

And the record ends genuinely on the page’s plane, not in the projection’s space. That is what makes the square legitimate where §W.9’s straightening was not: the straightening produced a square that shared no edge and no history with the drawing — it simply appeared — whereas this one shares the moment the reader watched it leave. The objection was never to a square; it was to a square with no account of how it got there. The turn is the transition between the two spaces, and it cannot be expressed in either — an isometric projection has no orientation at which a face is exactly face-on, so the turn is not a rotation inside the drawing, it is the record departing the drawing. That is the honest description and it is why the phase exists.

What the probe has to settle, since the shape is ruled and the timing is not. The split: 1000ms is fixed for phase one, and phase two is the open figure — faster than the pull is the hypothesis, since a turn covers less distance and a slow turn will read as a swivel. The seat stays empty from the first frame of phase one through the landed state, because it is the record’s absence rather than an animation of it. Put back is both phases reversed, in reverse order — round, then in.

W.16 · The turn is a rotation, and phase one is bounded by it

The record rotates rigidly in three dimensions and is re-projected every frame; its projected corners are never interpolated. The probe answers this by watching: interpolating the four corners from sheared to square passes the face through intermediate quadrilaterals that are no rotation of any record, so the shape morphs instead of turning. A rigid rotation has a signature the morph cannot fake — the widths of the cover, spine and top face change together as one solid — and §W.17 replaces this paragraph’s account of the signature, which named a narrowing that belongs to the direction the record does not turn.

The axis is the cover’s near vertical edge, which under §W.20’s viewpoint is the one at y = 150, not its centre. This paragraph has been written three times and the third version restores the first: its original ground was that the cover advances throughout, that was withdrawn when §W.17 appeared to reverse the direction, and §W.20’s sign correction reinstates it — so the withdrawal is withdrawn rather than a third account invented. The opening rotation carries the cover normal from (1, 0, 0) to (0.707, 0.707, 0), and against the viewpoint (1, 1, 1) that is 1.414 against 1: the cover turns toward the reader and every point of it advances. The near edge is the point the turn plants — it does not move, and no point of the record ends further from the reader than it. A centre pivot sends the far half backward into the row the record has just left while the near half swings out, which reads as a turntable and spends part of the 151 units the pull just bought. So the turn and the pull agree in direction, which is the requirement the pull imposes.

The clearance term §W.14 was missing, and it is derived rather than chosen. A 12 × 150 footprint pivoting about its near vertical edge (y = 150) sweeps within √(12² + 150²) = 150.5 of that axis, so phase one must travel the full 151 units before phase two may begin — about the centre axis it would be √(6² + 75²) = 75.2, so 76, which is the cheaper number and the wrong pivot. W.17 · Where the rotation stops and what finishes it

§W.16’s arrival claim is withdrawn: no rotation about a vertical axis ever squares the cover under this projection, and I ruled one that ends face-on two rounds after giving the reason it cannot. The measurement is exact — at 45° the cover’s horizontal edge projects to 183.7 against a constant vertical 150, which is 1.2247 : 1 and the best it ever reaches. The factor is √2 · cos 30, the amount by which a face diagonal projects longer than an axis edge, and it is the same constant that makes isometric drawings out of true projections. An isometric has no orientation at which a face is face-on because the projection, not the orientation, is what is oblique.

So the gesture is rigid to 45° and finishes with two terms, both of which are the projection being removed rather than shape being invented. At 45° the cover is an axis-aligned rectangle, upright and orthogonal on screen, and two things are still wrong with it: it is 22% too wide, and the body’s 12-unit thickness projects to an 8.49-unit sliver of edge below it — the rotated basis gives x̂ → [0, 8.49], ŷ → [−183.7, 0], ẑ → [0, −150], so the projected solid is 183.7 × 158.49 and not 183.7 × 150. So the finish is a horizontal compression of 0.8165 and the thickness term collapsing 8.49 → 0, and the second term is the one “taking the isometric out” actually names: the depth contribution (x + y) · sin 30 going to zero. An earlier version of this paragraph specified the compression alone and claimed width was the only fault, which would have landed the record at 150 × 158.49 — 1 : 1.057, a 5.7% band of edge under the cover — against §W.3’s cover at its own aspect, uncropped. 0.8165 is 1 / √2 · cos 30, the reciprocal of the factor that made it wide; and a face-on orthographic view of a box shows no thickness at all, so the sliver closing is the same event as the cover squaring rather than a separate flattening. Both terms reach zero together, which is why the finish reads as one move. The record does not leave the projection so much as the projection is undone on it, which is the account the paste-over objection asked for: the square is the 45° rectangle with the isometric taken out of it, and the reader has watched both halves happen.

The direction is the one that opens the face, and §W.16 had the signature backwards but not the direction. This clause said “backwards along with the signature” and it was wrong about the direction in a way worth tracing: §W.16 said the cover advances, this section appeared to reverse it, §W.16’s ground was withdrawn on that basis, and §W.20’s sign correction reinstated it — so §W.16 was right all along and this section’s apparent reversal was the withdrawn camera, not a disagreement. Away from the reader the cover’s horizontal edge runs 129.9 → 0 and shuts edge-on at 45°; toward the reader it runs 129.9 → 183.7 and opens — the figures are camera-independent and the toward/away labels were §W.15’s, so they swap under §W.20 and the conclusion below is unchanged. So the record turns toward the reader to show its cover — which is what the hand does: a record lifted spine-first has its cover facing along the row, and bringing it round is turning it to face you. This sentence read “turns away” until §W.20 fixed the viewpoint; the widening figures either side of it are camera-independent and unchanged, and this clause was the one part of the section that was not.

And the narrowing is withdrawn as the proof of rigidity, because it belongs to the direction that closes. The opening direction only widens, so it has no narrowing to show — but it has a better signature, and it is derived rather than chosen: the spine closes. The spine is the +y face (§W.20), 10.39 wide in projection at rest, and its normal turns exactly edge-on to the camera at 45° — the same angle at which the cover squares up. So spine width runs 10.39 → 0 and reaches zero precisely when the rotation ends.

That is the signature a corner interpolation cannot fake, and it is a stronger one than the narrowing was. A morph of the cover’s four corners has no spine and no top face to be consistent with; a rigid body shows three faces whose widths change together, and the reader reads rigidity from the agreement rather than from any one face. The cover widening while the spine closes at exactly the rate that keeps the solid solid is what says object. The 151-unit clearance stands unchanged — it is a fact about the swept volume and indifferent to which way the sweep runs (§W.16).

W.18 · Three clearances, and which one binds

Phase one travels 151 units, unchanged, and 363 is withdrawn as a requirement rather than adopted as a correction. The two figures answer different questions and there is a third that neither of them is: 151 is the sweep — the record can rotate without its volume touching a neighbour; 150 is the separating plane — the record is ordered in front of every record in the row; 363 is zero silhouette overlap — the record’s projected outline no longer touches the row’s at all. Only the first two are requirements.

The separating plane is the one the occlusion worry was really about, and it is satisfied at 150. Every neighbour spans y ∈ [0, 150]; travelling +y by d puts the pulled record at y ∈ [d, 150 + d], so at d ≥ 150 a plane on y separates it from all of them, and it is on the larger-y side, which under §W.20’s viewpoint is the near side — so it draws in front of the whole row regardless of x. This derivation ran along −y until §W.20 fixed the sign, which reached the right 150 by a route that sorted the record behind the row. The sort and the travel do different jobs and both are needed: at d < 150 the boxes still overlap in y, so the separating axis falls back to x — and a neighbour at larger x is genuinely nearer, so it correctly draws in front of the pulled record. The exact sort stops the order being wrong; it does not make the record front-most, and being in front of the whole row really is bought with 150 units of travel. An earlier version of this paragraph said the travel did not have to, which denies the requirement the same paragraph derives. What the sort does buy is that nothing is mis-drawn on the way there — and the 363 was measured without it, under centroid sorting, which is the moved-parameter shape again: a distance read off a defect in the paint order.

And zero overlap is not something to want. A record held out from the shelf it came from should cover part of that shelf — overlap is what depth looks like, and removing it puts the record beside the wall rather than in front of it, which is the composition §W.10 rejected when the square shared no edge with the drawing. At 363 the record has left the fixture; at 151 it is in front of it. The gesture is a record coming forward, not a record leaving.

One honest caveat about the margin, because this file has been caught by it three times: the two derived quantities are 150.48 and 150, which is 0.48 of a unit apart, and the shipped 151 clears the plane by a whole unit only because 150.48 rounds up. A gap of half a unit between two independently derived requirements is a coincidence rather than a margin, and a rounding is not a design decision. The sweep radius √(12² + 150²) and the plane’s 150 are both functions of the record’s depth, so they move together — but they are not the same function, and a thinner record or a shallower shelf separates them. Both are derived, so re-derive both whenever the box changes; do not treat 151 as covering the plane by construction.

The wrong-axis diagnosis does not apply here, and it is worth saying why the shape did not recur. 151 was derived over the rotation’s geometry and the rotation’s geometry is what it governs — it was never claimed to be the distance at which the row stops being drawn over the record, and that question splits in two: the sort answers whether anything is mis-drawn, and the plane’s 150 answers whether the record is front-most. Neither answer is 151, and neither is 363. The near miss was real though: had the order stayed centroid-based, the parameter would have been raised to 363 to fix a defect in the paint order, which is a distance standing in for a correctness bug and would have made the slide two and a half times longer for nothing.

W.19 · The phases overlap, and the landed composition

W.20 · The viewpoint, the pull’s sign, and how the record grows

§W.15 is withdrawn on the camera and the derivation is closed rather than argued: P(1, 1, 1) = [0, 0], so this projection collapses that direction and admits exactly two viewpoints, ±(1, 1, 1). §W.15 named (+∞, −∞, +∞), which is neither — P(1, −1, 1) is [1.73, −1] and not zero, so it is a direction the projection still draws. Withdrawn by §W.25: growth rides the rotation’s window, because an orthographic projection has no size change on approach — the paragraph below reasons from a perspective intuition this drawing does not have. What survives is that growth is not a third term. And the growth is not a third term — it rides the travel, because it is the same fact. A record that comes toward the reader gets larger; that is what approach looks like, and the probe’s constant-size rotation is why it read as turning in place rather than coming out. So scale is on phase one’s curve and completes when the travel completes, from the seat’s 150 to the landed 560 — 3.73× — with the rotation overlapping it as §W.19 rules.

Which answers the growing-while-turning question by making it not a choice: the record grows while it turns because it travels while it turns. Putting growth on its own window would need a reason, and there is none — a record that finished travelling and then grew would read as a picture being zoomed, and one that grew before travelling would read as approaching without moving. Tying it to the travel is the only version where the size at every instant is the size the distance implies.

W.21 · The finish’s window, and what the growth scales about

The rotation keeps its 1300ms and the finish is added after it, so the out-span is 1600ms and the probe’s measurement is not re-interpreted. 1300 and 700 were read off a gesture with no finish in it, so the finish is additional to what read well rather than carved out of it — carving it would shorten the travel and rotation that were the thing being judged. The return reverses the whole gesture on one clock at the same ratio: 700 × 1600 / 1300, so 860ms back.

300ms for the finish, and it is chosen rather than derived — said plainly because two constraints bound it and neither fixes it. It must be long enough that a 22.5% change of width does not read as a cut, and short enough that it reads as the record settling rather than as a third phase, which means shorter than the rotation it follows by a clear margin. 300 against 1300 is a ratio of about 1 : 4.3. It is the one number in the gesture a probe should overrule, and the probe that measured 1300 could not have measured it, because the gesture it watched had no finish.

And the growth scales about the foot of the pivot edge — the bottom of the cover’s near vertical edge at y = 150 — which is Claude Code’s shelf end made exact. The reason to prefer that point over any other is that the rotation already fixes that edge, so using its foot makes one point of the record fixed by both transforms at once. Any other origin has the growth moving a point the rotation is holding still, and the two then fight over it: scaling about the record’s own centre grows it backward through the shelf, and scaling about the region’s centre detaches it from the seat entirely.

So the record keeps its foot on the shelf and grows forward and up, which is the same relationship the pivot has to the rotation and the same one the offset has to the travel. Three transforms, one fixed point, and the whole gesture is then describable as: that corner stays put while everything else leaves.

Worth recording as a class, because it is the third time it has cost a round: a transform’s origin is invisible to every still. The drawings show the growth’s start and its end, and every origin agrees at both ends and disagrees only in between — which is exactly the shape of the corner-path question, where interpolated and rotated corners matched at 0° and 45° and differed at every angle between. A still cannot be wrong about these; it simply has nothing to say, and the tell is a parameter whose two endpoints are both given.

W.22 · The view pans; the gesture does not move

The drift is withdrawn and replaced by a pan: the record’s transforms stay exactly as §W.21 rules them, and the drawing region pans so that the landing is in frame. The gap is real and Claude Code states it exactly — the gesture is authored in the wall’s coordinates and the landing is specified in the page’s, and nothing was converting between them. A drift converts by moving the object; a pan converts by moving the viewport, and the wall already pans (§W.6), so this needs no new mechanism and no new page room.

That is why the drift’s second consequence is the one that rules it out. §W.21’s argument is that three transforms share one fixed point; a drift leaves them sharing a point that is itself moving, which is not a weaker version of the argument but the negation of it — the foot stops tracing what the travel gives it. Under a pan the foot is fixed in the wall’s coordinates exactly as ruled, and §W.21’s claim narrows correctly rather than approximately: the point is fixed in the frame the gesture is authored in, and the whole frame translates.

And the pan is the better reading, not merely the cheaper fix. A record drifting to meet the composition is the object accommodating the page; a view panning to follow the record is the reader stepping across to look at it, which is what a person does at a shelf. The fixture moving on screen during the pull is the cost, and it is the correct cost: the wall stays still relative to itself and the record, and only the window over it moves.

Mechanically: the pan rides the swing’s own ease on the same clock, so the gesture and the framing are one motion rather than two. It resolves to zero when the landing is already in frame, which is the property the drift had and worth keeping. Vertically it answers the top-shelf case by the same means — a record whose foot sits high needs the view to show more above it, which is a pan and not a layout allowance, so no vertical room has to be found in §W.13’s bands.

Two consequences to keep, both honest under the pan: a neighbour reached by the arrows lands in the same screen position, because the pan differs by exactly the seat pitch and equalises it — the same outcome the drift produced, now derived rather than arranged. And §W.19’s composition becomes a statement about the framed view rather than about absolute page coordinates: 560 square, left of the fixture, the empty seat clear — all of it true of the frame the pan arrives at, which is what a landed composition always was. §W.26 makes the clearance the pan’s target rather than a figure: the 55px stated here was measured on one seat of the drawing, and the pan has to clear the seat for every one of them.

The timed-out navigation tests are the finding worth recording: the gesture was correct and the page could not contain it. Every ruling in §W.16 to §W.21 is a fact about the wall, and a fact about the wall cannot by itself put anything on the page — which is the class §W.19 nearly hit when it derived an offset on two axes and could implement one. The tell is a ruling whose terms are all in one coordinate system and whose obligation is in another.

W.25 · Growth rides the rotation, not the travel

§W.20’s reason for putting growth on the travel is wrong, and wrong in a way that decides where growth goes — §W.21 is untouched by this ruling, and the distinction matters: §W.20 schedules the growth, §W.21 says what it scales about. §W.20 rules that a record coming toward the reader gets larger and that this is what approach looks like — but this is an orthographic projection, where approach produces no size change at all, by definition. A record travelling toward the viewer in isometric is exactly the same size at every distance; that is what makes the projection isometric. So growth is not approach. It is the record leaving the projection — which is precisely what the rotation is.

Growth therefore rides the rotation’s window, joining at 0.42, and the cause is shared rather than the schedule being convenient. Two transforms with one cause, one window and one fixed point, with the travel underneath — which makes §W.21’s shared-fixed-point argument sharper rather than weaker. Size does not change through the first third: the travel establishes the motion as a motion, and then the growth and the turn arrive together as one departure from the drawing.

The measurement is why the old distribution could not be tuned into working: 410px of growth against 290px of travel on one ease is a ratio of 1.41 at every instant. The size change is always half again the position change, everywhere along the curve — so it read as scaling rather than travelling structurally, not because the numbers were off. A constant ratio is the signature of two quantities sharing a curve when only one of them belongs on it.

The two alternatives, both weighed and both declined. Growing entirely after the travel would read as a zoom, which §W.20 rejected correctly — the section whose scheduling is withdrawn here got that much right — and this is not that, because the rotation’s window still overlaps most of the travel. And the finish is the other candidate with a real claim, being literally where the projection is removed; but 410px over 300ms is abrupt, and it would separate the size from the turn that shares its cause, which is the one relationship this ruling exists to establish.

Built as an adjustable window rather than a constant, like the finish’s 300ms — and for the same stated reason. The 0.42 join is a motion parameter, and this is the second one in the gesture that no still can judge (§W.21): the endpoints agree under every distribution and only the frames between them differ. What a still cannot judge, a ruling should not fix.

W.27 · The chrome on the drawn paper

The generic hairlines take §3’s value — 0.72 — and stop being a second scale. --border at 1.08:1 and --input at 1.15:1 are not rules a reader can follow; §3’s hairline is 0.72 on this paper and was chosen against it, and the app has been carrying two hairline values the whole time — one derived on the drawn ground and one on a ground nothing painted. §W.5 did not lower them, it made them measurable, which is the same shape as the 11px label at 3.88: a defect that predates every ruling and surfaces when the measurement moves to the ground the app paints.

And §3 already forbids the outcome, which is why this is a correction rather than a new rule: it spends its argument keeping a rule at the threshold of visible, and a rule at 1.08:1 is past that threshold on the wrong side. A hairline that cannot be seen is not a quiet rule, it is an absent one — the table’s rules and the search box’s edge are the structure those views are built from.

The chip surfaces invert rather than retune: a hover must sink, so it steps toward ink, not away from it. At 0.945–0.955 against a 0.925 ground they are lighter than the paper, so the gesture reads as lifting — and that is a behaviour reversing, not a ratio drifting, which is the more serious of the two. A number that drifts is wrong by a margin; a surface that was meant to depress and now rises is telling the reader the opposite of what it means, and no amount of tuning inside those values fixes the direction.

The value is the ladder’s shade step applied from paper: 26% toward ink, which is 0.731. §5.5’s steps are proportional — tint at 34% toward paper, shade at 26% toward ink — so borrowing the step means borrowing the proportion, not a lightness delta, and the proportion applied against paper is what a surface one step below paper means.

An earlier version of this ruling said 0.90 and called it the ladder’s step, and the figure disproves itself against this section’s own standard: 0.90 on a 0.925 paper is 1.08:1 — the exact ratio the hairline paragraph two above disqualifies --border for. It was a flat delta of 0.025 wearing a proportional step’s justification, which matched neither the 34% nor the 26%, and it would have inverted the direction while leaving the surface as invisible as the one it replaced. 0.731 reads 1.91:1 against paper — a surface a reader can see sink.

The general form, because it is what let a wrong number pass a paragraph arguing for the right principle: a proportional step and a fixed delta are not interchangeable, and a value quoted as “one step” has to name which. The chrome borrows the drawing’s steps rather than inventing its own, which is the whole content of this ruling — and a borrowed step is only borrowed if it is recomputed against its new ground. Both changes are one-line token edits and neither touches a drawing.

What this does not do is make the chrome part of the composition. §W.5 makes every ratio measurable against one paper and nothing more — the table, the grid and the search box stay the app’s chrome, ruled only where they contradict a value the drawings depend on. The two here contradict §3 and the ladder respectively, which is why they are ruled and the rest is not. Withdrawn within §W.27: the table, the grid and the search box staying the app’s chrome, ruled only where they contradict a drawing. Adam has ruled that the table and the grid are designed in the record page’s vocabulary, and they have their own target, Table and Grid - build target.dc.html. The two values this section sets still stand, and that target takes them.

W.29 · The desktop route opens near

§W.12’s “the route opens far” is withdrawn on the desktop: a bare / opens the near view, and the far view becomes a deliberate zoom-out. Worse here, because the threshold is invisible — a reader cannot see why their collection opened differently from someone else’s, and crossing 80 records would silently change what the app does on load. A fork the reader can see (§W.26’s viewport width) is a different object from one they cannot.

What opening near costs, stated because §W.28 refused to let the far view hide its emptiness and this must not hide its own: the fixture is 442 × 1047 at 1:1 in a 968 × 799 region, so it does not fit. Height is short by 248px — the arrival shows about three shelves of four — and width leaves 526px of the region empty at 20 seats. The first is answered by where it lands; the second is real and is the near view’s standing condition, not a defect of this ruling: a fixture narrower than its region is what a 20-seat shelf looks like, and §W.28 already refused to resize the fixture to fill space.

So the arrival lands on the occupied shelf rather than at the fixture’s top corner — the same target §W.28 gives a click on a run, and for the same reason: the empty shelves are the room the collection grows into, and a view that opens on them opens on nothing. The pan (§W.22) does the positioning; no new mechanism.

Nothing else moves. The far view keeps §W.24’s narrow shelf — below the fork the route still opens far, because there the near view is not a fixture — and keeps §W.12’s filter shape, stays reachable from the count, and Escape still reaches it. §W.28’s fit, click target and hover are untouched: this rules when the far view is entered, not what it is.

And the remembered-or-linked view composes rather than competing, once the view is in the URL: a bare / opens near, a linked view opens where it says. That is one constant now (DEFAULT_ROUTE_VIEW) and a URL parameter later; build the constant first, because a default is what a link is an exception to.

The arrival is in the markup: the first paint is already at the arrival, with no script between the stream and the position. This section ruled out the wall travelling into place and said nothing about how the position is reached. A scroll set by script cannot guarantee it: the script is after the region in the stream, so on a slow connection a frame paints at 0,0 first. Hiding the region until the script sets the scroll removes the travel and replaces it with a blank, measured at 1.8 seconds at 200 kbps and over six at 50. That is a worse state than the one it fixes: travel shows the wall late, blank shows nothing, and a wall that is not there for six seconds reads as broken.

So the region is rendered at its arrival position: the server computes the arrival and emits the wall already offset to it, with the region’s scroll at zero, so there is nothing to move and nothing to wait for. Reading order and focus are unchanged; only the painted offset is. scrollLeft is set once, after first paint, only so that the reader’s own scrolling starts from the arrival, and setting it must not change what is painted. The hidden-until-scrolled fix is interim: it stands until the markup offset lands, and then it is removed, not kept as a guard.

The general form: a position the page promises at first paint cannot depend on a script arriving. A state that exists only until a script runs is a state the reader sees on every slow connection, and it has to be ruled like any other state, not left as the gap between two rulings.

Without JavaScript the wall starts at its origin, whole and reachable: the offset is cleared by a noscript style, not by the landing effect. The markup offset is a transform the landing effect clears, so with JavaScript off it stays. Measured, it hides no row today: without script the server renders translate(-5px, -75px) whatever the shelf parameter says, because the addressed shelf is applied by the landing effect, so the offset covers 75px of landing pad and every spine stays reachable. The noscript style is still right, for two reasons. It makes the no-JS state the origin this section names rather than an offset nobody chose. And it removes a hazard the current server does not produce: if the server ever offsets to a later shelf, the strip above the arrival would become unreachable without script, which §W.8’s contract forbids. What a no-JS reader loses is only the arrival, a lost courtesy, not lost content. A scroll anchor was the alternative and is declined: it puts the arrival in the URL, so every shared link would carry a position the sender happened to have. The test asserts the origin, not reachability: reachability could not fail on the current server, so it tested nothing; with script off the offset’s computed transform must be none.

W.30 · Reaching the run by keyboard

The run is focusable, and it is a button rather than an anchor — which is where the parallel to §W.23 breaks and has to. A spine is an anchor because a record has a route; a run has none, and §W.29 makes the near view the default rather than a destination, so “the shelf” is a camera position and not an address. An anchor with no href is a link to nowhere announced as a link, which is worse for the reader it exists to serve than a control announced as what it is. It is a button labelled by what the hover says in ink: 17 records — zoom to this shelf.

Order: after the rail, before nothing — it is the last stop on the far view because it is the only one. The rail is the page’s chrome and the run is its content, and §W.24 put the filter in the rail precisely so the shape on the fixture is read after it is set. Tab order follows that sequence rather than reversing it. At more than one occupied run — any collection over a shelf’s worth — runs take document order, which is §W.23’s seat order one level up: top shelf first, because that is the order they filled.

Focus is the hover’s sink and count plus a 2px ink rule along the run’s front edge, and the addition is the point. Hover and focus must not be the same state: hover follows a pointer that is already where the reader is looking, and focus has to be findable by someone who cannot see where it went. The sink alone is a 1.74:1 change in a drawing made of 1.99:1 hairlines — legible as a response, not as a location. The rule is 0.18 on the 0.731 surface, which is 7.89:1, and it lies along the front edge because that edge is the run’s longest continuous line and the only one no spine interrupts.

2px because §3 already owns this: it is the weight reserved for a mark that is not a rule about type, and §W.27 has just spent the round making sure the app has one hairline value rather than two. A focus ring at any other weight would be the second tier §3 forbids. And the value is recomputed against its ground rather than borrowed: 0.18 reads 7.89:1 on the hover surface and 15.07:1 on paper, so it clears on both — which is the check §W.27’s closing sentence asks for, run before the value was chosen rather than after it failed.

What this does not do is give the far view a second control. §W.28 rules the run is the only target because the fixture is half empty shelves; keyboard access does not widen that — it reaches the same target by another route, which is the whole of §W.23’s argument for a tab sequence over a parallel list. W.33 · Hover and focus on a spine

No, a spine does not pull out on hover — and the reason is the one Adam’s question already contains. W.35 · The count’s mark, and what a sort moves

The count carries the arrow — THE WHOLE COLLECTION → in 11px mono beneath the figure — and the set bar is refused. §W.13’s 44-wide bar means this is the current state: it marks the active view name and, under §W.32, a set filter. Putting it under the count would say the count is set, not that it is pressable, and a state mark on a control is worse than no mark because it reads as an answer rather than an offer.

The arrow is already this page’s departure mark and it is already in both views: §W.19’s panel ends OPEN THE FULL RECORD → and §W.28’s run hover reads 17 RECORDS →. So the mark is the same in both views and only its timing differs — at rest on the near view’s count, on hover on the far view’s run. The far view’s own count does not carry it: there is nowhere to go, since you are already looking at the whole collection — because the far view’s run is the whole drawing and its count is the thing withheld, while the near view’s count is already on screen and only its pressability is not.

And this is not the caption §W.28 refused. That refusal was about explaining a drawing — a label on a control is the control’s name, not a gloss on a picture, and the page has carried arrow-labels since §W.19 without any of them explaining anything. Adam reporting the far view as missing is the measure of the defect: a pointer cursor and an accessible name are not marks, and 72px of ink that does nothing else on this page is a display figure until something says otherwise.

The sort reordering the wall is intended, and §W.1 already licenses it: position carries the collection’s order, not a record’s address. The sort chooses which order, so moving everything is what position-carries-order means rather than a violation of it. The fixed frame §W.1 protects is the fixture — seats, pitch, row length — and none of that moves under a sort; what moves is which record sits in which seat, and the label is the identifying channel precisely so that position does not have to be.

§W.34’s footprint is unaffected, because it is read within one arrangement rather than across two. A footprint says a record was displaced from this seat, in this order — it is a statement about the filter, not a memory of where something used to live, and re-sorting redraws both the records and their vacancies together. The one thing a reader loses is positional recall across sorts, which §W.1 already declined to sell them.

Section order remains the tie-break under a chosen sort, as built. A sort names one key and the collection is full of ties — a shelf of records that share a year would otherwise arrange themselves differently on each load, which is the determinism §W.1 depends on and the same reason spineWidth hashes rather than randomises. W.36 · The set bar leaves the flow

The bar comes out of flow: it is drawn against the label’s baseline and occupies no height, so the switcher’s pitch is one number whether a view is set or not — 42, per §W.37. Not a fixed row height — that would absorb the bar by reserving space for it on every row, which is the same 8px spent invisibly instead of visibly, and it would make the rail’s rhythm a consequence of the widest possible state rather than of the type.

The reason is what the bar is: §W.31 settles that a mark that stops is not a rule that failed to reach, and this is the other half of it — a mark is not content, so it cannot push. A bar that displaces its neighbours makes the rail’s spacing encode state, so GRID sits 8px lower when SHELF is active than when it is not, and a set filter moves the switcher. Position in the rail is the reader’s map of the page’s controls; a map that shifts when you use it is not one.

And it generalises to §W.32’s reuse, which is why this is worth a ruling rather than a build note: the same bar marks a set filter, and GENRE and SORT sit above the switcher — in flow, a set filter would push every view name down, so choosing a genre would move the control you choose the view with. Out of flow, setting anything moves nothing.

One correction to accept from the build: a rail without GENRE is legitimate — §W.24 renders the facet only where facets exist — so omitting it is a claim rather than a gap. It asserts a collection with no genres. The four drawings were nonetheless stale rather than deliberate, since each draws a seventeen-record collection whose panel sets PRESSING, PROVENANCE and MATRIX, and §W.28’s pair predate the ruling by generation order. But the distinction stands for the next reader: an absent control in a drawing says the state that hides it, and a drawing cannot abstain.
