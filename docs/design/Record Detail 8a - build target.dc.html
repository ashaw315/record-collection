Three standing rules on measurement, placed first because §17, §19, §20 and §22 were spent on a constraint one measurement would have dissolved (§23). One: any ruling that changes a figure another drawing depends on reports the measured before and after against the supplied render, with its threshold named — derived numbers are not a substitute. Two: any change to a cell or band dimension names its delta in the section that makes it; §2.1 named two adjustments and omitted the 77px one that mattered, and that omission is checkable. Three: a reading of the render is cited only if it was measured, with the threshold stated — reading it by eye produced 480 and 452 in §23, both wrong. A derivation inside the file and a measurement of the render are different acts, and only the second can tell the file it has drifted.

Every ruling is looked at, section by section. Render the sections a ruling touches, view them, and record what was seen. A file too large to render whole is a fact about the file, not a reason to leave a round unviewed. The last four rounds found only defects of look, and no automatic check could have seen them.

A value that varies by width is never held inline. Four build defects this session were that one shape: §28’s breakpoints doing nothing in step 20, the twelve columns pinned flat from 1440 to 1679, the lower region holding twelve columns to 1920, and a fourth recorded with them at docs/findings/ in 323cfdf. It is the build-side twin of a drawn instance read as a rule: a figure correct at the width it was written for, written where nothing re-derives it at another. So any value a breakpoint changes lives in one place that the breakpoint reads, never in the element that uses it.

A declared value is not a measurement. A test that reads a declared value asserts its own input: §28’s band declared 547 and rendered 387.5, because an !important elsewhere won the cascade. It is the build-side twin of a drawn instance read as a rule, and the index spec committed it too: assertion 8b checked a column it had defined rather than the column the table has, so it passed on empty strings. Measure the used value, or the rendered box.

Before fitting a constant, check the measurements are of the same thing. §26’s build fitted one right inset to two figures, 243 and 203, when the drawing encodes two rules by host: two columns in a full-width strip, centred in an air column. The evidence that they disagreed was recorded beside the constant. And a rule drawn from two instances must name the cause, not the correlation: §26 first named solo and pair because they moved with the host.

A wrong constant that produces a visible regularity is harder to catch than one that produces a mess, because the regularity reads as intent. Both figures landing on x = 1200 is what let the error survive.

A section says a thing once. If a later sentence needs the same subject, it points at the first rather than restating it. A restatement is a second source that can go stale against the first, and a partial restatement reads as a complete rule: §26 stated the tint triangle’s placement twice, and the second statement omitted the bleed, so a build read it as flush. It is the excerpt defect at paragraph scale, and unlike a handoff row nothing warns the reader.

A test whose passing depends on the defect. A unit test asserted the triangle’s max-width: 25%, which equalled §29’s cap on the visible part only because the triangle bled nowhere. With the bleed built correctly, the visible part is less than the box, so the test was green only while the build was wrong. That is not a test that cannot fail; it is one that would have failed on the correct build. Assert the quantity the rule names — here the visible part — not a property that coincides with it in the defective case.

Flat solid colour is admitted on this screen, and it does not contradict §W: §W’s rest state is the wall’s. The values are the ladder’s and nothing else: tint, base and shade of the record’s own derived colour (§5.5). Flat shapes take tint where they are ground and base where they are a mark; shade stays a face of a solid, because a shade with no object to belong to is just a darker rectangle.

The isometric solids already take the ladder on their three faces — top tint, left base, right shade — in every drawing in this file, so §13 rules nothing new about them and the forms and geometry stand as §9.2 has them (four archetypes fixed per section, height at 0.62 of the section, the two-thirds visible gate, half a column of clearance from a control). So the dullness is a build defect against §5.5 and §9.2, and it is in §12’s fixes. The matrix still is excluded: §5 captions it record-independent, so its three grey faces are the one place the ladder must not reach — and a fix stated as “the solids stop being grey” would have coloured exactly that one.

And two flat shapes per region, no more: one tint field as ground in the last section’s widest cell (§9.4) and one base rectangle as a mark in an empty cell above it. Two rather than “a few”, because §9.4’s floor and the one-mark-per-section rule are what stop ornament becoming pattern, and a third flat shape makes the region read as a layout with colour blocks rather than a page with marks in it. This is the app’s ornament vocabulary from here: isometric solids in the record’s three tones, flat fields in tint, flat marks in base, and no hue that was not sampled.

Same shape as §W.36’s pitch: a figure that looked like a constraint turned out to be a value, and the rule derived over it inherited the stiffness rather than the requirement.

15 · No, and where the sampled colour does belong

No — and the decisive objection is not the premise, it is that hover would make the pull redundant on its own subject. §W.19’s gesture means this record is now itself, and its content is the colour arriving. If the colour has already arrived by the time you press, the pull delivers a cover you have seen the colour of and a panel — it stops being a transition and becomes a zoom, which is the thing §W.20 refused and §W.25 reasoned about from the other side.

And the case for it does not survive §W.1, which is the part worth stating because it is where the argument sounds strongest. The claim is that a sampled colour identifies rather than decorates — but §W.1 already rules that the label identifies, and the label is on the spine’s face at rest. Hover reveals nothing the reader cannot already read, so colour on hover is decoration wearing identification’s justification. A channel that only appears on demand, on the element that already names itself, adds a second answer to a question that was answered.

§W.33 stands unchanged: sink to 0.731, hairlines 0.588, nothing else, and §W.32’s exclusion of even the app’s own accent stands with it. A hover that painted would also break what §W.28’s hairline correction protects — 0.588 was derived as §5.5’s shade step from 0.731, and against a sampled ground of any lightness it is no longer a step from anything, so every spine’s separation would become a function of its own cover.

So the boundary, stated once so the question does not return: the sampled colour belongs to a record that is out of its seat, and to nothing that is in one. Not per view and not per element — per state of the record. A seated spine is line, ink and paper whether hovered, focused, filtered or sorted; a record in flight and a record landed carry their colour, and so does the record screen, because §13 rules that page the place the pull arrives.

That is why the landed cover’s field is legitimate on the same page the hover is not — both are on the shelf, and one of them is a record that has left its seat. And it answers the version of this question that will come next: a selected spine, a recently-viewed spine, a spine matching a search — all seated, all line and ink. The far view’s run is the same rule applied to twenty records at once, so it does not colour either.

One thing confirmed rather than ruled: the record screen using the sampled value is correct and not a leak from an earlier build. §5.2 derives it, §5.5 makes the ladder from it, and §13 admits flat colour there on the ground that the page is the pull’s destination. What the app had at some point was this value on a seated spine, which is the one place it has never been ruled to belong.

17 · The arrangement takes the cell’s aspect (withdrawn by §20)

Withdrawn by §20 — the drawing is width-bound, so matching the cell’s aspect lowers the scale and takes the floor from six failures to nine. The account below is kept for its diagnosis of the dead height, which is real, and not for its remedy. None of the four: the frame’s aspect changes, because the arrangement was composed without reference to the box it lives in and that is the whole defect. 0.903 against a 0.659 cell is not a fitting problem — it is a composition that was laid out in free space and then posted into a box, so 147px of dead height and 73% occupancy are what a mismatch of that size looks like. The generator arranges forms into a box of the cell’s proportion; the drawing then fills its cell in both directions, nothing spills, nothing is cropped, and the scale that clears §5.5’s floor comes free.

And this is available where the other three are not, because the arrangement is not the page’s composition. §8 closes the frame — the bands and the cells — and §12 keeps the pass off it; the construction’s internal arrangement is the generator’s — §5.1 makes it one of the eight marks derived per record, and this section supersedes §5.4’s “same image on all seventeen” for the identity still (its matrix clauses stand) — so re-proportioning its bounding box changes no cell, no band and no projection. An earlier version of this sentence cited §5.4 as licence, which is the section that forbids it: §5.4 was written when both stills were placeholders, and the generator that replaced the large one arrived without it being marked. Placement was always the hash’s business; this constrains the space it places into.

The box alone does not deliver this — §19 supplies the missing term, a rotation of the arrangement in plan — and with it the reasoning below holds. The floor clears by scale alone, at or above Code’s figures: filling height gave a 0.600% minimum and a 1.091% median, and filling both directions cannot be smaller than filling one. Which also explains why §5.5’s own remedy failed — the sweep from 1.05 to 1.45 reached 0.494% and left two records failing: growing a face inside a drawing that occupies 73% of its cell is spending the wrong term. The area was short because the drawing was small, and the drawing was small because its aspect was wrong.

The other three are refused on named grounds rather than on preference. Cropping puts a cut object in a cell — the Edge Marks ruling is that a cropped object reads as a mistake where a cropped field reads as a plane, and this is an object. Widening the cell is a band change §8 closes. And changing the archetype set to make the cube-coloured records clear a number is the derived-from-the-set defect exactly: the cube is small by design (§5.5, stating the 6:1 band as a fact about the generator’s set), so resizing it to satisfy a floor would tune the vocabulary to the measurement it is measured by.

Two things are preserved and must survive the re-proportioning, because each was a fix for a defect this file already paid for. The spread — six slots ringing one origin gave a centre-weighted cluster, and a narrower box is exactly the condition that re-clusters it, so the 6:1 size band and two forms breaking the disc’s edge stay as stated. And the per-record offset within the shared frame is the signal, not drift: fitting per arrangement is what once made six records look like one drawing, so 35 units of vertical variation is the hash showing through a frame that does not normalise it away.

18 · What the identity cell does when the artist does not fit

The type never moves. The grid does. §4.2 names the sizes and forbids 16 to 39, and a remedy that gives the artist a smaller size below some width adds the tier §4.2 exists to prevent — it would not be a responsive rule, it would be a fourth size with a media query for a justification. So the answer is not a size and not a clip: the content track floors at 412, §4.2’s give order runs as it already rules — its ordering is that section’s and is not restated here — and below the width where 412 plus its chrome no longer fits, the page is one column.

The floor is derived rather than picked, which is what makes it a rule: 412 is the measure §4.2 already sets the type to. A track narrower than its own measure is not a squeezed composition, it is a different one — which is why the build’s collapse-to-min-content test wrapped titles at 196: it let the track find a width from the content instead of giving the content the width the type was designed for. 19 · The ring rotates in plan, then the forms rise

The ring keeps its shape and its spread exactly under both. Re-proportioning the ring cannot reach the target and would not have worked — shrinking its footprint reduces screen width and screen height together, since both x and y feed the vertical term, so a squeezed ring is a smaller arrangement at the same aspect. That is why §17’s “arrange into a box of the cell’s proportion” looked unsatisfiable: the lever everyone reached for moves both axes at once.

What moves one axis is orientation. A ring elongated along the x − y diagonal projects wide; the same ring along x + y projects narrow and tall, because that diagonal is the one the projection sends vertically. Between them the projected aspect falls monotonically, and the interval on which it does is 0° to 45° — an eighth turn, not a quarter. The curve is symmetric about 45°, so over a quarter turn every target has two roots, the second being the mirrored plan, which flips which forms break the disc’s edge. The generator solves on 0°–45°, where the root is unique.

The two endpoints are different kinds of thing: the upper is a constant of the projection and the lower is the generator’s to measure — an earlier version of this paragraph had both moving. At 0° the x − y and x + y ranges are equal for any centrally symmetric ring, so the aspect there is cos 30 / sin 30 = 1.732 at every width; at 45° the width term is the ring’s own width, so the minimum is about 1.732 · b/a and rises with it. Which leaves one open question rather than a correction: the build’s ring measures 1.804, and no width can lift the 0° aspect above √3 — so that figure was taken on something other than the bare ring, the ring plus the forms’ z-extent being the obvious candidate, or the ring is not centrally symmetric. The generator must say which, because the feasibility test below is derived from the upper endpoint being that constant.

And the lower endpoint rising is a feasibility condition, testable before any rotation: the minimum over the interval is about 1.732 · b/a, so a target of 0.658 is reachable only while the ring’s width-to-length ratio is under 0.38. At 0.4 the whole interval bottoms out at 0.693 and at 0.6 it never falls below 1.0 — so rotation is exhausted at any appreciable width, and this is the likely case rather than the remote one. When it fails the next term is the forms’ own height, ruled here rather than mentioned: z enters the vertical term alone, so raising the forms lowers the aspect at every heading and does it without touching the plan — which keeps the isometry guarantee below intact, since the spread is a property of the plan. Rotate first because it costs nothing; raise second because it changes the silhouette. 24.2° is the root for the bare ring and is a sighting shot, not the answer.

And this is the protection §17 asked for, stated rather than assumed: a rotation is an isometry, so every pairwise distance in the spread is preserved by construction. The centre-weighted cluster was a spacing defect and spacing is exactly what a rotation cannot change — the 6:1 size band, the slots’ separations and the two forms breaking the disc’s edge all survive because none of them is a property of the plan’s heading. Re-proportioning would have had to be argued; rotating is guaranteed.

The floor is not reconsidered, and the third option is refused on §17’s own ground. §5.5’s 0.5% was set on a drawing whose aspect was wrong, which makes it worth re-checking and does not make it wrong — changing the measurement because the thing measured fails it is the defect this file has refused twice, at the archetype set and at the withdrawn ceiling. Both halves of that sentence are withdrawn by §20: the drawing is width-bound, and §17’s mechanism was wrong.

Which is §18’s shape once more and worth naming as a pair: a rule that fixes a container and expects its contents to follow is one term short. §17 set the box and left the arrangement free; the box then constrained nothing, because a nearly square arrangement fits a tall box by leaving air. 21 · The ornament library

One vocabulary, and the library is the frame generator’s archetype set — licensed by §5.1 as one of eight marks derived per record, counted at six in §9.2, its arrangement ruled by §20 — with no new forms. What the library holds is arrangements: the solo figure and the pair. The six are the beam, the slab, the cube, the plate, the panel and the line, and this is the file’s canonical list — every other section cites it rather than naming them. §9.2 gives two proportion triples — beam 0.8 × 0.8 × 7.6 and plate 2.8 × 2.8 × 0.28 — and describes the panel as upright without dimensions; §5.5 names the slab in passing. This section states the remaining proportions as its own rather than quoting them: cube 1 × 1 × 1, panel 2.4 × 0.3 × 3.2, slab and line to be measured off the generator. An earlier version of this sentence attributed all four to §9.2, which holds two, and the cube and panel figures were recalled from the generator script rather than read from the file — the inherited-not-measured class (§W.28, §W.30, §20), committed inside the paragraph correcting an enumeration from memory. Until now no section listed all six, so the earlier remedy here — cite rather than re-list, borrowed from §18 — pointed at an enumeration that did not exist and steered a reader away from the only section naming the slab. Citation replaces re-listing only where a canonical list exists; where none does, the governing section becomes it. They span the shape space the projection can express, and adding figures so ornament is more interesting is the same move as widening the archetype set to clear a floor, which §17 and §20 each refused. A second set could not read as a second system in any case: an isometric cube in a construction and an isometric cube in a library are the same object, so the only thing a parallel vocabulary would add is two names for one thing.

So the unit of the library is the grouping, not the shape. A solo figure is one archetype at the section’s height (§9.2); a pair is two archetypes whose footprints do not overlap in plan and whose silhouettes do overlap in projection — that overlap is the whole reason a pair is a different mark from two solos, because it is what makes the two read as one object in space. §9.2’s 0.62 governs the pair’s combined box, not each form, so the two are correspondingly smaller and the pair passes the same gate a solo does — 0.627 of the cell against a two-thirds ceiling, the figure §9.2 already measures. Applying 0.62 to each form instead makes every pair illegal by construction: disjoint footprints project to a vertical offset, so two 0.62 forms exceed the ceiling whatever their heading. A pair therefore trades size for structure — each form is smaller than a solo would be — which is the honest cost of spending one mark’s allowance on two objects. Three is not in the library, and the file has already refused it once: §10.3 rules that three marks at the drawn size read as a row of specks rather than as one mark — it converts a presence problem into a pattern — so this is §10.3 applied to the library rather than a new ceiling. What limits repetition is §9.4’s one-mark-per-section rule, paired with its floor as §13 states the pair; an earlier version of this sentence cited the floor alone, which is a minimum area and cannot bound a count — only a count or a ceiling can, and §13’s sentence names both halves where this one had dropped the operative one. A third form also turns a mark into a composition that competes with the construction.

Curved forms are admitted and free-drawn ones are not, and the line between them is construction. The disc is not an archetype — it is the ground the construction stands on (§5.4), which is why it takes tint and why it is not a figure a page may place solo or paired — but it is precedent for curvature in the drawing: a circle in plan, projected to an ellipse, drawn by the same projection as the solids. So the rule rests on a construction test rather than on the disc’s membership: a curved ornament is a primitive in plan — circle, arc, annulus — laid on the ground plane or on a face and projected with everything else. What is refused is the free silhouette, because it has no construction and therefore no answer to why it is that shape rather than another, and a mark whose shape is arbitrary is decoration in the sense §5.4 forbids. Organic, here, means curved in plan; it does not mean drawn by hand.

An isometric figure never crosses a page edge. A flat field always may. That is not a new rule — it is the Edge Marks ruling, and §19 and §20 are its consequence rather than a separate prohibition: a cropped object reads as a mistake and a cropped field reads as a plane extending past the view. So Adam’s masked mode belongs to the flat shapes and not to the figures, which is also why §13 gives the flat pair their own count.

A figure may be clipped by the cell that owns it, and §9.2 depends on it: the gate measures visible height precisely because the region solid’s bottom bleed is deliberate, and no one-column solid could pass a total-box test. That is occlusion rather than cutting — a cell edge has the next section behind it, so a figure running under it reads as continuing; a page edge has nothing behind it, so a figure crossing one reads as severed. An earlier version of this section said a figure never bleeds and never crosses a cell edge, which made §9.2’s drawn solids defects and its gate unsatisfiable at once.

The flat field’s test is the one that needs a threshold, statable so a build can check it: a field bleeds at a page edge, never at a cell edge, and at least a third of it lies outside the frame. The first clause is load-bearing — a field cut by an internal boundary is a field that did not fit its cell, and nothing about its geometry says otherwise — and the second stops a mark that merely touches the edge from reading as a near miss. The asymmetry is the point: a figure may be occluded and may not be severed, and a field may be severed because a severed plane is what a plane from outside looks like. A third is a threshold, not a measurement, and it is stated as one; what it has to be is large enough that no reader wonders whether the shape was meant to end there.

A page’s ornament is fixed per screen and written down, never hashed. Fixed means which ornament and where, not its size; sizes follow the host at render (§29). §9.2 settled this for the region and the reason generalises: a hash makes ornament encode which record or which page you are on, and §5.4 rules that ornament carries no data. “No data” means no hashed data: no per-record identity. It does not mean no information. §9.2 has always sized solids against a box whose height depends on content, and §29 sizes flats the same way, so a flat on an About cell with no snippet is visibly smaller than one on a full cell. Ornament has therefore always said something about how full a cell is. What it never does is say which record this is; that is the construction’s job alone. Read as “no information at all”, this sentence would forbid what §9.2 requires. The construction is the sole exception in the app because it is the record rather than a mark about it — the frame’s ornament is the record’s, everything else’s is the screen’s — and a second hashed mark would undo that distinction by making two things vary for different reasons in the same drawing.

Narrowed by §26: a pair is available in a §9 region’s air column, because an air column is a section carrying no construction — the condition this section gives the six screens. It stays unavailable in any section with content.

Two units, and they are not the same: figures are counted per section and flat shapes per region. At most one figure per section, which is §9.2’s unit — and §9.2 caps solids at one per section, so a pair is not available inside a §9 region. The withdrawn version of this cap said two solids per section and rested the pair on it; §9.2 says “one per section”, so the pair’s whole permission was a miscount of the section it cites by number in the same clause. Where the pair is available is the six screens the library exists for: a section that carries no construction has nothing for a second solid to compete with, and the pair takes §9.2’s obligations on its combined box — the gate on visible height, and the clearance from a control measured from the pair’s outer extent rather than from either form. Plus §13’s two flat shapes per region, one tint field as ground in the last section’s widest cell and one base rectangle above it. A screen may have fewer of either. The withdrawn version of the unit rule counted figures per region, which capped them four times too low and made §9.2’s four drawn solids — beam, plate, cube, panel, one to a section — defects. The ceiling is not a target; §W.28 refused to resize a fixture to fill space and the same holds here, so a screen with nothing to decorate decorates nothing. And each screen names its own figures in its own spec rather than drawing from the library at random, which is what makes six screens share a vocabulary instead of sharing a random number generator.

What keeps this one system rather than two is that the library adds no form and no value. The forms are the frame generator’s, enumerated in this section, the values are §13’s and the ladder they step on is §5.5’s, the bleed rule is Edge Marks’, the count is §9.4’s, the per-screen fixing is §9.2’s. The forms were attributed to §5.5 here through three rounds of correcting the same misattribution elsewhere in this section — §5.5 owns the ladder and not the set. The library’s original content is four things: the pair, the plan-primitive rule for curves, and the bleed test’s two clauses — page edge not cell edge, and a third of the shape outside. Edge Marks rules which marks may bleed; where and how much are new here, and the one-third is a threshold this section chooses, as it says of itself above. All four are constraints on how the existing set is used rather than additions to it, which is the claim that survives; this paragraph opened with “nothing in it is new” until now, which was true of the forms and the values and overstated for the rest. A vocabulary that grows to meet each new screen is not a vocabulary; it is a record of what each screen wanted.

31 · The frame is a stated constant, and arrangements must fit it

The frame stops tracking the collection. It is fixed at a stated extent, and an arrangement that does not fit it is illegal, so the hash moves to that record’s next arrangement. This is the same mechanism §22 uses for colour eligibility, applied to the frame. The extent is the union step 18 measures on the current collection, written into this file as a number once measured. After that it is a constant, not a result.

The reason is §5.1’s rule, not the margin. The eroding margin was the symptom that raised this; the cause is that a purchase could repaint a record already drawn. A frame fitted to the collection’s extremes is a mutable input to every record’s drawing. Buying one record with a wider arrangement rescales all the others, and through §22’s guard it can change an existing record’s colour placement or even its arrangement. §5.1 forbids feeding the drawing anything that changes, and the collection changes every time Adam buys a record. With a fixed frame, a record’s drawing depends only on its id and on constants, so adding a record never changes one already drawn.

That also settles the margin: adding records cannot erode it, but fixing the constant did, once. The union is 294.7735 wide and the constant is 296, because flooring the origin to −140 pushed the left edge out while the right still had to be covered. Scale falls by 0.9959 and area by 0.9917. Measured: worst 0.5084% at 1440 × 900, median 0.7535%, worst 1.2547% at 390 × 844. The 1440 anchor now has 1.68% of margin and is the tightest point in the system, and the band rule does nothing for it, since it only applies above 1440. The 0.513% figures elsewhere in this file were measured before the constant was fixed. Scaled by 0.9917 they become about 0.610% at 1680 × 1050, 0.557% at 1920 × 1080 and 0.526% at 1679 × 1050. Measured in step 22: 0.610%, 0.559% and 0.524%, with the worst at 1440 × 900 0.5084%, the median 0.7535%, and the worst at 390 × 844 1.2547%. The original sentence read: it cannot erode. The worst existing record is 0.513% at the fixed frame, and new records cannot widen the frame. A new record’s own colour lands on a form that clears the floor at that scale, by §22’s guard. So the floor holds for every future record by construction, not by a margin.

When §22’s guard binds, it does what it was written to do. §22 expected it to bind nowhere, and that stays true of the current collection, because the frame is that collection’s union. It may bind for future records, moving the colour to another eligible form or advancing the arrangement. That is deterministic and depends only on the record’s id. Binding on a new record is not a failure; it is the guard working.

The cost, stated: arrangements wider than the current widest become unavailable to new records, so the hash lands on them less often. The clamp that made this true is removed. containedOrigin moved forms back inside the frame before drawing. That is the normalisation §17 forbids, applied at exactly the extremes where the per-record offset must show, and §32 withdrew the height floor on the same ground. The fit check now does the work: a record whose forms fall outside the frame takes the hash’s next arrangement. The cost, measured: over 5,000 ids, 690 records (13.8%; 14.1% in step 24’s run) had at least one form displaced, by up to 40.92px on a 296-unit frame. So about one new record in seven takes an arrangement other than its hash’s first choice. That is a real narrowing of the variety, not a slight one at the extreme. None of the current seventeen is displaced, so none changes and the frame constant stands. This replaces the sentence that said the variety “narrows slightly at its extreme”, which was written before the rate was measured. Adding slack to the frame would keep them, but it lowers every record’s scale and therefore the floor. So the frame is exactly the measured union, with no slack. Step 23 reports how many hash outcomes the frame rejects, so the narrowing is a number rather than a guess.

The constant is the measured union rounded up to the next whole unit, and the rounding is the tolerance, not slack. At full precision the widest current record would fit by exactly zero, which makes its fit an equality: a coincidence, not a margin (§W.18). Rounding up costs every record the same scale, at most 1 ÷ 432 = 0.23%, which is 0.46% of area. Measured, it is 0.41% of scale, because flooring the origin grows the box on both sides of each axis, not only the extent. The worst record goes from 0.513% to 0.5084%. Fit is asserted at render as well as in the measuring pass, because §27’s fixture path and the render path could differ by a rounding, and the point of §31 is a constant both agree on.

No id may exhaust its arrangements, and if one ever does, its fallback is ruled here. The hash advances at most 32 times, for either reason: an arrangement that does not fit the frame (§31), or one whose colour has no eligible form (§22). Step 23 samples the id space, asserts no sampled id reaches the cap, and reports the largest number of advances any id needed. The cap is a guard, not a test. At the measured 14.1% rejection rate, an id reaching 32 advances has a probability of about 10⁻²⁷, so the assertion that none does cannot fail and is evidence of nothing: this file’s class of a test whose outcome is insensitive to its premise. The evidence is the rate and the depth: 14.1% over 5,000 ids, deepest 5 of 32, no quiet ids, and none of the seventeen changed when the clamp came out. The cap exists so that a pathological id terminates, and the fallback below is what it terminates into. At the cap, the fallback depends on which test failed:

No arrangement fits the frame: the id’s first arrangement is drawn, scaled down just enough to fit. Only that record’s scale is lower, and it depends only on its id.

An arrangement fits but no form can carry the colour: the record renders quiet, with its construction in greys and no base face. The page already has this state: records whose cover gives no usable colour render quiet (§5.2), so the reader sees a state the collection already contains, never a blank cell. §5.3’s null-spine fallback, a record with no drawing at all, is the wrong precedent. Here the record has a drawing; it is its colour that has nowhere legal to land.

What happens to the extremes fixture: it still exists to test the extremes (§27), but the frame is no longer derived from it. The fixture now checks that every current record fits the stated frame and clears the floor at it.
